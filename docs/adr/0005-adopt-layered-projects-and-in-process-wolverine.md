# Adopt layered projects and in-process Wolverine

MDSweep adopts Motion's API, Application, Domain, Infrastructure, AppHost, ServiceDefaults, and Web project shape while retaining MDSweep's vertical feature ownership. Domain state and rules have no MDSweep dependencies. Application owns command/query contracts and results. Infrastructure owns EF Core, file parsing, Keycloak administration, clocks, and handlers that use those adapters. API owns the HTTP and authentication boundary.

Wolverine is approved for in-process command/query dispatch, Wolverine HTTP endpoints, PostgreSQL-backed technical persistence for managed conjoined tenancy, and Lightweight EF Core transaction middleware. Mutating handlers use the non-generic Application persistence `IRepository`; its generic operations are intentional because `ApplicationDbContext` implements the interface used by `WithDbContextAbstraction<IRepository, ApplicationDbContext>()`. `AutoApplyTransactions()` infers persistence without transaction attributes; commands and queries do not carry transaction attributes. Ordinary resource lists use typed query contracts with code-defined Ardalis specifications evaluated by EF Core through that repository. Two workflow-preserving commands keep an explicit EF Core save instead: Driver access creation must compensate by deleting the newly created Keycloak user if the local commit fails, and assignment must translate a database uniqueness race into the existing HTTP 409 response. Neither command uses Wolverine transaction middleware. Durable business workflows, inboxes, outboxes, scheduled jobs, sagas, and Wolverine-managed application migrations remain outside this refactor. During this synthetic, pre-production refactor, the EF Core migration history was intentionally reset to a single `InitialSchema` baseline for the MDSweep application database. Synthetic databases created from the removed chain must be recreated, and the reset baseline must never be applied over a production or real-data database. A tested production migration, backup, and restore procedure is required before patient-linked data is introduced.

The Angular application uses lazy workflow routes, Tailwind, a minimal generated Spartan control set, TanStack Query for non-persisted server state, and TanStack Table for dense Trip management tables. The existing durable Driver action queue stays separate from TanStack Query.

This decision retains the current Keycloak authorization-code BFF, HttpOnly application cookie, same-origin token-free Angular client, one Keycloak realm per environment, one MDSweep database plus a separate Keycloak database, manual MTM Manifest input, and manual MTM billing-file output. Middleware beyond Wolverine's EF unit of work, authorization redesign, email, outbox, and jobs remain outside this refactor.
