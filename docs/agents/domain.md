# Domain Docs

This is a single-context repository.

## Before relevant work

- Read the root [CONTEXT.md](../../CONTEXT.md) before naming domain concepts in issues, tests, code, or UI text.
- Read ADRs under [docs/adr](../adr/) that affect the area being changed.
- If a referenced document is absent, continue silently; domain documentation is created only when language or a durable decision is resolved.

## Vocabulary

Use the canonical terms defined in `CONTEXT.md`. Avoid synonyms that its entries reject. When a needed project-specific concept is genuinely missing, resolve it through domain modeling rather than inventing competing language inside an issue or implementation.

## Decisions

Surface contradictions with an existing ADR explicitly. Do not silently override or reinterpret an accepted decision.
